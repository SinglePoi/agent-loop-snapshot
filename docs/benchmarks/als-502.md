# ALS-502 性能、并发与故障注入

更新时间：2026-09-07

## 基准

在 Node.js `v24.20.0`、pnpm `11.19.0` 的 `win32-x64` 开发机上运行：

```bash
pnpm benchmark:als-502
```

每个脚本输出 JSON，方便保留原始数据或由 CI 收集。`ALS_BENCHMARK_EVENT_COUNT` 可覆盖事件数；基线场景分别为：

- `benchmark:recorder`：10,000 个事件、JSONL batch flush（每 100 个事件）和终态 manifest；报告端到端记录时间、吞吐与持久化字节数。
- `benchmark:trace`：100,000 个事件的流式加载、校验与索引构建；报告加载时间、吞吐和进程内存增量。
- `benchmark:graph`：已加载的 100,000 个线性事件构建因果 DAG；报告纯投影时间、吞吐、节点和边数。

阈值用于同一机器的回归预警，不作为跨机器的 CI 硬失败条件：

| 指标 | 基线工作负载 | 目标阈值 |
| --- | --- | ---: |
| Recorder 吞吐 | 10,000 事件，batch-100 | >= 1,000 events/s |
| Recorder 磁盘占用 | 10,000 事件，batch-100 | <= 1,000 bytes/event |
| Trace Loader | 100,000 事件 | <= 5,000 ms |
| Graph 投影 | 100,000 线性事件 | <= 5,000 ms |

首次 ALS-502 本机运行结果如下：

| 指标 | 结果 |
| --- | ---: |
| Recorder | `6320.37 ms`，`1582 events/s`，`446.77 bytes/event` |
| Trace Loader | `1244.62 ms`，`80346 events/s`，RSS `77.90 MB`，Heap `85.07 MB` |
| Graph 投影 | `290.23 ms`，`344558 events/s`，`100000` nodes，`99999` edges |

现有 Trace Loader 的三次中位基线为 `2446.90 ms`，详见 [trace-loader-100k.md](trace-loader-100k.md)。首次 ALS-502 基准结果应和 Node、平台与事件数一起记录；数值跨机器比较前须先复测三次并取中位数。

## 并发与故障注入

`JsonlWriterFaultInjector` 与 `ArtifactStoreFaultInjector` 是显式测试钩子，不会在默认生产路径启用。回归测试覆盖：

- 500 个共享父事件的并发 Recorder 调用：事件 ID 唯一、序列无间隙、因果父节点保持不变；延迟到达的调用按实际到达顺序提交。
- JSONL 写入失败：写入失败的事件不会进入 Recorder 的内存记录、不会推进序号或终态；磁盘上的快照保持未提交状态，并被 `inspectSnapshotDirectory()` 标记为 `UNFINISHED_RUN`。
- Artifact 写入失败：抛出 `ARTIFACT_WRITE_FAILED`，并清理临时文件；不会产生可枚举 artifact。
- Artifact 篡改：`verify()` 返回 `ARTIFACT_DIGEST_MISMATCH`，`get()` 拒绝读取篡改后的内容。
- JSONL 尾部截断：已完整落盘的事件仍可读取，尾部以 `PARTIAL_JSONL_TAIL` 诊断返回。

因此，失败路径不会生成“看似成功”的可验证快照：终态 manifest 仅能在已完成的写入序列后显式原子提交，任何缺失或损坏内容均通过结构化错误或快照诊断暴露。
