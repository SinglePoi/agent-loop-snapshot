# ADR-0003：事件顺序、身份、时钟与错误模型

- 状态：已接受
- 日期：2026-09-06
- 决策者：项目维护者
- 关联任务：ALS-001

## 背景

快照需要同时表达追加写入顺序、并行分支和汇合。单一的全局时间戳无法可靠表达因果关系；多个进程或多个 Runtime 实例也不能依赖进程内计数器生成事件身份。错误还必须可审计，但不能把 Secret、授权头或未脱敏的异常堆栈写入快照。

## 决策

### 身份

- `run_id`、`event_id`、checkpoint ID 和 replay run ID 使用密码学安全随机源生成的 UUIDv4，并在持久化对象中使用带语义前缀的字符串，例如 `run_<uuid>`、`evt_<uuid>`；
- ID 不依赖进程内计数器、时间戳或机器名，因此不同进程生成的 ID 不会发生可观测的确定性冲突；
- ID 一旦写入快照不得改变；Replay 使用新的 `run_id`，并通过 manifest 记录 `source_run_id`；
- ID 只用于身份和引用，不用于排序。消费者不得从 UUID 的字典序推断事件先后。

### 顺序与因果

- `sequence` 是单次 Run 内的稳定写入顺序，从 1 开始、单调递增且不重复；
- Recorder 负责为进入持久化边界的事件分配 `sequence`。并发分支按实际被接受并写入的顺序获得序号；
- `parent_ids` 表达因果关系，可以包含多个父事件，用于表达并行汇合；
- 并行调用不能仅凭 `sequence` 被解释为串行调用；图投影必须优先使用 `parent_ids`；
- 事件的父节点必须在同一 Run 中存在，且写入时应已进入当前事件之前的持久化边界；合并事件可以拥有多个已完成分支作为父节点；
- `sequence` 只保证单个 Run 内的写入顺序，不用于跨 Run、跨进程或跨机器排序。

### 时间

- `timestamp` 使用 UTC RFC 3339，至少精确到毫秒；它用于展示、审计和跨环境比较，不用于建立严格因果关系；
- `monotonic_offset_ms` 使用 Recorder 进程的单调时钟计算，表示相对本次 Run 开始的耗时；它不能跨 Run 比较，也不能在进程重启后延续；
- 如果系统时钟回拨，`sequence` 和 `parent_ids` 仍是正确性依据；时间线只能标记时钟异常，不能改写历史事件。

### 错误模型

- 可预期的模型、工具、校验和策略失败以结构化事件保存，例如 `tool.failed`、`model.failed` 或 `run.failed`；
- 错误 payload 至少包含稳定 `code`、面向用户的已脱敏 `message`、`retryable` 和可选的 `kind`；
- 每次重试是新的调用事件，必须通过 `parent_ids` 和 correlation key 关联到原始尝试，不能覆盖失败事件；
- Recorder 生命周期非法转换、JSONL 损坏、引用缺失等协议或加载错误属于诊断，不得伪装成成功事件；
- 所有错误消息、异常堆栈和 adapter 返回值在持久化前经过脱敏；原始 Secret 不得出现在事件、日志或错误输出中；
- 未捕获异常导致进程中断时，已刷盘事件保持有效，Run 由 Loader 标记为未完成或不完整，而不是猜测一个 `run.completed`。

### 版本策略

- 所有持久化对象携带 SemVer 风格的 `schema_version`；
- patch 版本只修正文档、校验诊断或不改变结构的实现细节；
- minor 版本可以增加向后兼容字段或事件类型。读取器必须忽略未知字段，并将未知事件作为不可执行的 opaque event 保留诊断；
- major 版本表示不兼容变更。默认拒绝加载为可执行 Trace；未来 CLI 可以安全查看元数据，但不能开始回放；
- 迁移必须生成新的快照目录，不能原地覆盖源快照；每个迁移步骤必须可重复执行并验证输出；
- `events.jsonl` 的事实事件和 Workflow IR 的 schema 版本分别演进，不通过隐式转换混用。

## 备选方案

### 使用进程内递增整数作为 event ID

不采用。它在多进程、重启和合并 Trace 时会冲突，且无法作为稳定的跨边界引用。

### 用时间戳排序并推断因果

不采用。系统时钟可能回拨，多个事件可以共享时间戳，并行事件的完成时间不代表因果关系。

### 失败事件覆盖为重试成功事件

不采用。这样会破坏审计事实，无法分析失败原因或验证重试策略。

### 发现错误后直接原地升级快照

不采用。不可变源快照是回归测试和迁移报告的依据，升级结果必须写入新的目录。

## 后果

### 正面影响

- 因果 DAG、线性时间线和调用树可以从同一事件流得到；
- 多进程和并发场景不依赖中心化 ID 服务；
- 失败与重试可审计，Loader 可以区分不完整运行和业务失败；
- 协议升级有明确边界，旧快照不会被静默改写。

### 代价

- Loader 和 Graph Projector 需要同时维护 sequence 索引与 parent 索引；
- 单调时钟只在单个进程内有意义，跨进程耗时需要使用时间戳并明确误差；
- UUIDv4 不提供字典序时间排序，调试工具必须显式展示 sequence 和 timestamp；
- 脱敏规则属于持久化安全边界，错误配置必须通过测试和诊断暴露。
